<InShort>

The pages of the tools documentation are MDX files in `content/docs/tools`, listed in `lib/docs/tools.ts`. This page shows each component they are built from, with the MDX that produces it.

</InShort>

Every guide follows the same outline, so readers always know where they are: in short, a fact sheet, why it matters, the steps with their expected output, a check that it worked, the likely failures, and the next steps. Write short sentences, define each term the first time with `<Term>`, show the output of every command, and say why before how.

## Commands and output

### A command that is the same everywhere

```sh
npx @hos-ai/cli --version
```

A fenced block marked `sh` becomes a command with a copy button.

### What hos prints

```output id="producer-fail"
Producer urn:hos:pms:demo
✗ manifest.json: manifest that fails the checks (1 error)
  error   limitations is empty. A producer states its known gaps, unsupported states and access constraints, which the Event Producer checks require.
          rule events/producers · at /limitations
✓ recording.jsonl: 5 facts, valid and declared
✗ redelivery.jsonl: 1 fact, 0 already in the recording unchanged (1 error)
  error   line 1: pms-new from urn:hos:pms:demo is not in the recording. Publishing the same data again, a producer publishes the same facts with the same ids, so consumers discard them as duplicates.
          rule events/at-least-once-delivery · at /id

✗ urn:hos:pms:demo fails the producer checks.
```

A fenced block marked `output` colours ✓ and ✗ and each message level, and links every rule to its explanation. Copy the output from a real run, or from the snapshots in `packages/cli/test/__snapshots__`.

Every output block has an id, written after the language: `output id="validate-ok"`. `tests/unit/docs-examples.test.ts` runs hos for each id and compares, so a page never shows a message hos no longer prints. For output that another program prints, such as PowerShell, write `output from="powershell"` instead.

## A new page

1. Add the page to `lib/docs/tools.ts`, with `written: false` until its text is complete.
2. Write `content/docs/tools/<file>.mdx`, and add it to `app/docs/tools/[[...slug]]/content.ts`.
3. Once the page is written, set `written: true`: it enters the sitemap and search engines.
